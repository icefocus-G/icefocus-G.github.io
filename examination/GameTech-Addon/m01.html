1 先摆正位置：运行时官方仍推荐 UGUI

⚠
坑先说清楚一件事，免得学错方向。 截至 Unity 6.3 / 6.5，官方 UI 系统对比文档里写的仍然是：运行时推荐 uGUI，UI Toolkit 是「alternative（替代方案）」；编辑器推荐 UI Toolkit。所以 UI Toolkit 不是「UGUI 的接班人」，现在也不是运行时的默认选择。学它是为了在数据密集的场景用对工具，不是为了全面替换 uGUI。

Unity 里同时存在三套 UI 方案。最容易犯的错，是用 UGUI 的思维去写 UI Toolkit——把每个元素都当 RectTransform，然后发现布局怎么都对不上。

维度UGUI（Canvas）IMGUI（OnGUI）UI Toolkit
渲染场景内 Canvas，走 UI 合批立即模式，每帧重绘保留模式，独立渲染管线
布局RectTransform + 手动锚点代码里算坐标Flexbox（USS），像写网页
样式Inspector 逐项调GUIStyleUSS 类 CSS，可热重载
列表自己写复用池自己算ListView 自带虚拟化
擅长游戏内 HUD、世界空间 UI编辑器工具、快速调试数据密集界面、复杂列表、编辑器扩展
运行时全版本全版本2021.2+

它现在还缺什么，这张表比「它有什么」更能帮你做选型。以下是官方对比文档里明确标为不支持的：

能力UI ToolkitUGUI影响
与 Animation Clip / Timeline 集成不支持支持需要时间轴编排出场的 UI 动画，只能留在 UGUI
序列化事件（Inspector 里连回调）不支持支持只能在代码里注册，策划改不了
场景内可视化编辑（In-scene authoring）不支持支持必须在 UI Builder 里编辑资源文件
◆
核心判断标准：界面元素超过 50 个、需要滚动列表、需要主题切换 → 选 UI Toolkit；需要世界空间跟随 3D 物体、需要粒子/Shader 叠在 UI 上、需要 Timeline 编排 → 还是 UGUI。两者可以在同一个项目里共存，实际项目里混合使用才是常态。

2 三件套：UXML / USS / C#

UI Toolkit 的界面由三种文件协作，和网页的 HTML / CSS / JS 一一对应。理解这个映射关系，学习成本会立刻降一半。

网页UI Toolkit职责
HTMLUXML（.uxml）元素结构与层级
CSSUSS（.uss）外观与布局
JavaScriptC#行为、数据、事件
UXML
<!-- HealthBar.uxml：容器 + 底槽 + 填充 + 文字 -->
<ui:UXML xmlns:ui="UnityEngine.UIElements">
  <ui:VisualElement name="hp-root" class="hp-root">
    <ui:VisualElement name="hp-fill" class="hp-fill"/>
    <ui:Label name="hp-text" text="100 / 100" class="hp-text"/>
  </ui:VisualElement>
</ui:UXML>
→
建议UXML 是资源文件，运行时用 VisualTreeAsset 实例化。也可以纯 C# 建树（new VisualElement()），但结构一复杂就没法维护——除非是动态生成的格子，否则不要纯代码建树。

3 UXML 结构与常用控件

所有控件都继承自 VisualElement。容器本身也是 VisualElement，靠 flex 布局嵌套——没有「容器控件」这种特殊类型。

控件用途关键点
VisualElement通用容器默认 display:flex，铺满父级
Label文本支持富文本标签
Button按钮clicked 事件
TextField输入框注意移动端软键盘遮挡
Toggle开关值变化用 ChangeEvent<bool>
Slider / SliderInt滑条ChangeEvent<float>
ScrollView滚动容器内容多时优于普通容器
ListView虚拟化列表只渲染可见行，背包必备
Foldout折叠组设置面板分组
ProgressBar进度条血条/经验条可直接用
ⓘ
背景UXML 里 name 属性是唯一标识，C# 靠它查找；class 属性是样式选择器，可以多个。和网页的 id / class 完全同构。

4 USS：背下这 8 个属性就够用

游戏 UI 的布局有 95% 只用到 Flexbox 的少数属性。把这几个吃透，比拼凑各种偏方有用得多。

属性作用常见值
flex-direction主轴方向row / column
justify-content主轴对齐flex-start / center / space-between
align-items交叉轴对齐center / flex-end / stretch
flex-grow剩余空间占比0 / 1
flex-shrink空间不足时收缩0（不收缩）/ 1
width / height尺寸px / % / auto
padding / margin内边距 / 外边距四向可单独设
gap子元素间距省掉一堆 margin
USS
.hp-root {
  position: absolute;      /* 绝对定位到屏幕上某个位置 */
  top: 24px; left: 24px;
  width: 240px; height: 28px;
  background-color: rgba(0, 0, 0, 0.55);
  border-radius: 14px;
  overflow: hidden;
  justify-content: center;
  align-items: center;
}

.hp-fill {
  position: absolute;
  left: 0; top: 0; bottom: 0;
  width: 70%;                       /* C# 里改这个值就是改血量 */
  background-color: rgb(220, 60, 60);
  transition: width 0.25s ease-out; /* 掉血带动画，不需要写协程 */
}

.hp-text {
  color: #fff;
  font-size: 13px;
  -unity-font-style: bold;
  -unity-text-align: middle-center;
}
⚠
坑USS 不是完整 CSS：不支持 @media、对 ::before/::after 支持有限、calc() 在旧版本不可用、没有 float。写之前先确认当前 Unity 版本的 USS 支持范围，否则会白调半天。

5 C# 驱动：查询、事件、动态创建

C#
using UnityEngine;
using UnityEngine.UIElements;

public class HudController : MonoBehaviour
{
    [SerializeField] UIDocument doc;
    [SerializeField] VisualTreeAsset slotTemplate;   // 拖一个 .uxml 进来

    VisualElement fill;
    Label text;

    void OnEnable()
    {
        var root = doc.rootVisualElement;

        // Q<T> 用 name 查；也可以 Q<Button>(className: "btn")
        fill = root.Q<VisualElement>("hp-fill");
        text = root.Q<Label>("hp-text");

        root.Q<Button>("btn-settings")?.RegisterCallback<ClickEvent>(_ => OpenSettings());

        // 动态创建：拿模板实例化，再塞进容器
        var slot = slotTemplate.Instantiate();
        slot.Q<Label>("slot-index").text = "1";
        root.Q<VisualElement>("bag-grid").Add(slot);
    }

    public void SetHp(int cur, int max)
    {
        float pct = max <= 0 ? 0f : (float)cur / max;
        fill.style.width = Length.Percent(pct * 100f);
        text.text = $"{cur} / {max}";
    }
}
事件类型触发时机
ClickEvent点击（含触摸）
ChangeEvent&lt;T&gt;值变化：Toggle / Slider / TextField
PointerEnterEvent / PointerLeaveEvent指针进入 / 离开
PointerDownEvent / PointerUpEvent按下 / 抬起
KeyDownEvent键盘按下
GeometryChangedEvent尺寸或位置变化（做自适应布局时用）
→
建议元素还没布局完就读取 resolvedStyle.width 会拿到 0，因为布局发生在下一帧。要么等 GeometryChangedEvent，要么用 schedule.Execute(...).ExecuteLater(0) 推迟一帧。

6 数据绑定：两种，别混用

方式适用代价
序列化绑定（bind-path + SerializedObject）编辑器扩展、Inspector 替代品运行时性能差，且依赖 SerializedObject
运行时手动刷新（推荐）游戏内 HUD / 背包要自己写刷新方法，但完全可控

游戏内界面几乎都应该用手动刷新：数据变了就调用一次 SetXxx()。它比绑定更啰嗦，但没有隐藏开销，也不会在你不想刷的时候刷。

C#
// 反例：每帧反射式刷新，帧率越高越亏
void Update() => label.text = player.hp.ToString();

// 正例：只在数据变化时推
public void OnHpChanged(int cur, int max) => SetHp(cur, max);

// 绑定事件而不是轮询
player.OnHpChanged += OnHpChanged;
void OnDisable() => player.OnHpChanged -= OnHpChanged;  // 别忘了退订

7 实战一：血量条（三件套齐全）

把第 2、4、5 节拼起来，就是一个能跑的 HUD 血条。关键在于填充条用绝对定位 + width 百分比，而不是改 scale——改 scale 会让圆角和描边变形。

  • 结构：hp-root（底槽，overflow:hidden + 圆角）→ hp-fill（填充，绝对定位 left:0）→ hp-text（文字，居中）
  • 数值：fill.style.width = Length.Percent(pct * 100)
  • 动画：USS 的 transition: width .25s 直接生效，不需要协程
  • 变色：低于 30% 时给 root 加 class，用 .hp-root.low .hp-fill{ background-color: #ff3b30 }
⚠
坑不要用 style.width = pct * 240（硬编码像素）。父容器尺寸一变就全错，而且高分屏下对不上。始终用百分比。

8 实战二：背包列表（ListView 虚拟化）

背包有 200 格时，for 循环建 200 个元素会明显卡顿，而且滚动时全程占内存。ListView 只创建可见的十几行，滚动时复用。

C#
ListView bag;

void BuildBag(List<Item> items)
{
    bag = doc.rootVisualElement.Q<ListView>("bag-list");

    bag.makeItem = () => slotTemplate.Instantiate();      // 造一个空壳（只造可见数量）
    bag.bindItem = (el, i) =>                             // 把数据填进去（滚动时反复调用）
    {
        var it = items[i];
        el.Q<VisualElement>("icon").style.backgroundImage = new StyleBackground(it.icon);
        el.Q<Label>("count").text = it.count > 1 ? it.count.ToString() : "";
        el.Q<VisualElement>("sel").EnableInClassList("on", i == selectedIndex);
    };
    bag.itemsSource = items;       // 数据源
    bag.fixedItemHeight = 88;      // 固定行高是虚拟化的前提
    bag.selectionType = SelectionType.Single;
    bag.Rebuild();                 // 数据变了要 Rebuild
}
◆
核心虚拟化的前提是固定行高。如果格子高度不一，ListView 会退化成全量渲染，性能优势消失——这种场景改用 ScrollView + 自己做池。

9 实战三：设置面板（Toggle + Slider）

C#
void BindSettings()
{
    var root = doc.rootVisualElement;

    var music = root.Q<Toggle>("tg-music");
    music.value = PlayerPrefs.GetInt("opt.music", 1) == 1;
    music.RegisterValueChangedCallback(e =>
    {
        AudioListener.volume = e.newValue ? 1f : 0f;      // e.newValue 而不是 music.value
        PlayerPrefs.SetInt("opt.music", e.newValue ? 1 : 0);
    });

    var sens = root.Q<Slider>("sl-sens");
    sens.lowValue = 0.1f; sens.highValue = 5f;
    sens.value = PlayerPrefs.GetFloat("opt.sens", 1f);
    sens.RegisterValueChangedCallback(e => PlayerPrefs.SetFloat("opt.sens", e.newValue));
}
→
建议回调里一律用 e.newValue，不要回读控件的 .value。滑块拖动时两者可能不一致，而且回读会让「程序改值」和「用户改值」纠缠在一起。

10 落地模式：什么场景配什么做法

游戏 UIUI Toolkit 做法要不要用
HUD 血条 / 弹药ProgressBar 或绝对定位填充条 + USS transition推荐
背包 / 商店网格ListView + 固定行高 + 选中态 class推荐
主菜单 / 设置UXML 分文件 + Foldout 分组推荐
技能栏ListView 横向模式 或 固定数量 Button可选（数量少用 Button 更简单）
对话系统ScrollView + 逐字机（定时追加 text）推荐
跟随 3D 物体的血条——用 UGUI + World Space，别硬套

11 坑与最佳实践

  • 面板数量控制：每个 UIDocument 是一次 Draw Call。把常驻 HUD 合成一个 UIDocument，弹窗各自独立。
  • display 与 visibility：display:none 不参与布局、不渲染；visibility:hidden 保留布局、不渲染。做显示隐藏动画时用后者。
  • 不要每帧改 style：改 style.width 会触发布局重算。数值没变就别赋值，或加脏标记。
  • 资源释放：动态 Instantiate 的 VisualTreeAsset 记得在关闭面板时 RemoveFromHierarchy，否则越积越多。
  • 移动端软键盘：TextField 在 Android 上会顶起画面，需在 UIDocument 的 PanelSettings 里配好缩放模式。
  • 字体：UI Toolkit 用的是 FontAsset，不是 Font。中文字体要先做子集，否则包体暴涨。
  • PanelSettings 资产：一个项目通常一个，负责缩放模式（Scale With Screen Size）和分辨率参考值——这是全局的，别每个界面各建一个。
