1 先分清三个版本维度

ⓘ
背景和 Unity-Games 的分工：Unity-Games 里已经有大量商业化讨论——广告聚合该选 MAX 还是 TopOn、哪些节点做成变现点、皮肤包怎么定价。那些回答的是「该做什么」。本篇回答的是「怎么写」：SDK 怎么初始化、回调来了怎么分发、两套区域配置怎么在一份代码里共存、打包时怎么切。两篇不重复，接着看。

「国际版 / 国内版」不是一个开关，而是三个独立维度的叠加。很多项目一开始只按「区域」分，做到后面发现小游戏和 App 的广告 SDK 根本不是一套 API，只能推倒重来。

维度取值影响什么
平台形态App（iOS / Android）、小游戏（微信 / 抖音）广告 SDK 完全不同：App 用原生 SDK，小游戏只能用平台 JS API
发行区域海外、国内广告平台、支付通道、隐私合规、审核规则
内容合规GDPR / CCPA / ATT（海外）、版号 / 实名 / 防沉迷（国内）初始化顺序、权限弹窗、SDK 采集范围
◆
核心推荐组合策略：一个工程 + 多套 asmdef + 一套构建脚本。不要维护两份工程副本——两份副本三个月后必然分叉，改一个 bug 要改两遍，还经常漏。

2 程序集切分：让不该编译的代码根本不参与编译

这是整个方案的地基。用 asmdef 的 Platform 过滤 + Define Constraints，让国内版工程里根本不存在 AdMob 的代码——不是「运行时不用」，而是「编译时不存在」。

程序集内容约束
Game.Ads.Core接口、数据模型、工厂无平台依赖，全平台编译
Game.Ads.AdMobGoogle Mobile Ads 实现仅 Android / iOS，且 USE_ADMOB
Game.Ads.MaxAppLovin MAX 聚合实现仅 Android / iOS，且 USE_MAX
Game.Ads.Pangle穿山甲实现仅 Android，且 USE_PANGLE
Game.Ads.GDT优量汇实现仅 Android，且 USE_GDT
Game.Ads.MiniGame微信 / 抖音小游戏实现仅 WebGL，且 WECHAT_MINI / DOUYIN_MINI
JSON
// Game.Ads.AdMob.asmdef
{
  "name": "Game.Ads.AdMob",
  "references": ["Game.Ads.Core"],
  "includePlatforms": ["Android", "iOS"],
  "defineConstraints": ["USE_ADMOB"],
  "versionDefines": [
    { "name": "com.google.ads.mobile", "expression": "1.0.0", "define": "HAS_ADMOB" }
  ]
}
⚠
坑defineConstraints 不满足时整个程序集不参与编译——这正是我们要的。但注意：如果 Core 里有代码直接 new AdMobProvider()，就会编译失败。所以 Core 只能依赖接口，实例化必须交给工厂。

3 统一广告抽象层（整个方案的地基）

三个角色，缺一不可：接口定义能力、工厂决定实例化谁、门面收敛调用入口。业务层永远只跟门面说话。

C#
// ---- 1) 接口：只暴露业务真正需要的能力 ----
public interface IAdsProvider
{
    void Init(AdsConfig cfg);
    bool IsReady(AdSlot slot);
    void Load(AdSlot slot);
    void Show(AdSlot slot, Action<AdResult> onResult);
    void SetConsent(bool personalized);
}

public enum AdResult { Shown, Reward, Closed, Failed, NotReady }

// ---- 2) 工厂：用宏决定实例化谁 ----
public static class AdsProviderFactory
{
    public static IAdsProvider Create()
    {
#if USE_MAX
        return new MaxProvider();
#elif USE_ADMOB
        return new AdMobProvider();
#elif USE_PANGLE
        return new PangleProvider();
#elif USE_GDT
        return new GdtProvider();
#elif WECHAT_MINI || DOUYIN_MINI
        return new MiniGameProvider();
#else
        return new NullAdsProvider();   // 编辑器 / 无广告构建：什么都不做
#endif
    }
}

// ---- 3) 门面：业务唯一的入口 ----
public static class Ads
{
    static IAdsProvider p;
    public static void Init(AdsConfig cfg) { p = AdsProviderFactory.Create(); p.Init(cfg); }

    // 激励视频：拿到 Reward 才发奖
    public static void ShowReward(string slotId, Action<bool> onRewarded)
        => p.Show(slotId, r => onRewarded(r == AdResult.Reward));
}
◆
核心NullAdsProvider 不是凑数——它让「编辑器里没接 SDK」也能正常跑通全部业务流程。没有它，团队一半人会卡在「我本地跑不起来」。

4 广告位配置：不要硬编码 ID

广告位 ID 一定会变（换账号、换平台、A/B 测试）。硬编码在代码里，每次改都要重新出包审核。用配置表按区域分档。

JSON
{
  "region": "overseas",
  "slots": {
    "reward_double_coin": {
      "type": "rewarded",
      "providers": {
        "max":    "a1b2c3d4e5",
        "admob":  "ca-app-pub-xxx/yyy"
      },
      "cooldownSec": 30,
      "dailyCap": 20
    },
    "inter_level_end": {
      "type": "interstitial",
      "providers": { "max": "f6g7h8i9j0" },
      "minIntervalSec": 60
    },
    "banner_menu": { "type": "banner", "providers": { "max": "k1l2m3n4" } }
  }
}
  • 按 region 分文件：ads_overseas.json / ads_cn.json，构建时按宏挑一份打进包
  • slot 用业务语义命名：reward_double_coin 比 reward_01 好维护一百倍
  • 频控参数也进配置：冷却、每日上限都在表里，改策略不用发版

5 国际版：AdMob + AppLovin MAX

国际版通常用 MAX 做聚合、AdMob 做兜底。聚合的价值是自动比价——同一个广告位同时问几家，谁出价高给谁。

⚠
坑两条选型级的硬事实，官方文档里写着但很容易漏。 ① Unity Ads 明确不可用于中国大陆安卓流量（官方帮助中心原话是「中国大陆安卓流量不要使用 UnityAds 进行广告创收」）——这正说明区域分流不是过度设计，而是必须做的事，同一套广告栈在两地根本不能通用。② 聚合主 SDK 与各家 Adapter 的版本必须同步升级。比如 MAX 从 11.x 升到 12.x 而 Adapter 没跟着升，广告请求能发出去，回传却会静默失败：日志里没有 error、只有一堆 warn，后台表现是填充率莫名掉一半。这种问题排查极费时间，升级时把主 SDK 和全部 Adapter 一起升，别自己组合版本。
平台定位特点
AppLovin MAX聚合（Mediation）接多家广告源，自动比价；内置 A/B 与远程配置
Google AdMob单一广告源 / 也可聚合填充率稳，eCPM 中等；与 Firebase 打通
C#
// 合规顺序极重要：先拿同意，再初始化 SDK
public class MaxProvider : IAdsProvider
{
    public void Init(AdsConfig cfg)
    {
        // 1) GDPR：向用户征询（欧洲）
        MaxSdk.SetHasUserConsent(cfg.GdprConsent);
        // 2) CCPA：美国加州「不要出售我的信息」
        MaxSdk.SetDoNotSell(!cfg.CcpaOptIn);
        // 3) ATT（iOS 14.5+）：必须在 SDK 初始化之前弹
        //    App Tracking Transparency 授权，否则 IDFA 拿不到，eCPM 直接腰斩
        MaxSdk.SetConsentFlowEnabled(true);

        MaxSdkCallbacks.OnSdkInitializedEvent += _ =>
        {
            MaxSdkCallbacks.Rewarded.OnAdLoadedEvent += (id, info) => cache[id] = AdResult.Shown;
            foreach (var s in cfg.RewardedSlots) MaxSdk.LoadRewardedAd(s);
            foreach (var s in cfg.InterstitialSlots) MaxSdk.LoadInterstitial(s);
        };
        MaxSdk.InitializeSdk();
    }
}
⚠
坑ATT 顺序错了 eCPM 会腰斩：iOS 上如果先初始化广告 SDK 再弹 ATT，SDK 会在无 IDFA 状态下完成初始化，后续即便用户同意也拿不到设备标识。这个顺序必须写进代码注释，否则新人重构时会调回来。

6 国内版：穿山甲 / 优量汇 + 服务端校验

平台归属备注
穿山甲（Pangle）字节跳动国内 eCPM 较高，激励视频强
优量汇（GDT）腾讯填充稳定
GroMore穿山甲系聚合国内做聚合的主流选择
C#
// 国内 Android 必须在初始化前完成隐私合规声明
public class PangleProvider : IAdsProvider
{
    public void Init(AdsConfig cfg)
    {
        var ctx = UnityPlayer.currentActivity;
        // 1) 用户是否同意隐私政策（不同意就不能初始化）
        TTAdSdk.Init(new TTAdConfig.Builder()
            .AppId(cfg.PangleAppId)
            .AppName(cfg.AppName)
            .UseMediation(true)
            .SetPrivacyCompliance(new TTAdPrivacyComplianceConfig.Builder()
                .SetLimitPersonalAd(!cfg.PersonalizedAds)   // 个性化广告开关
                .Build())
            .Build(), _ => { /* 初始化完成后再 Load */ });
    }
}

国内做激励视频，服务端校验（SSV）不是可选项。客户端回调可以被篡改，发奖逻辑必须由自己的服务器向广告平台核验后再下发。

流程
客户端：Show 时带上透传参数（订单号 + 用户 ID）
   ↓
广告平台：用户看完 → 平台服务器回调你的 /ad/reward?token=...
   ↓
你的服务器：验签 → 幂等检查（同一 token 只发一次）→ 发货
   ↓
客户端：轮询 / 长连接拿到发货结果 → 刷新 UI
◆
核心判断标准很简单：奖励有真实价值（金币、复活、抽卡）就必须走 SSV。纯展示类（插屏、Banner）不需要。

7 小游戏版本：微信 / 抖音

小游戏跑在 WebGL 上，不能接入原生广告 SDK。只能用平台提供的 JS API，通过 jslib 桥接进 Unity。

平台广告 API特点
微信小游戏wx.createRewardedVideoAd / createInterstitialAd需在后台开通流量主，有资质门槛
抖音小游戏tt.createRewardedVideoAd同理，走抖音开放平台
JS
// Plugins/WeChatAds.jslib —— Unity 侧调到这里
mergeInto(LibraryManager.library, {
  ShowRewardAd: function (slotPtr, cbPtr) {
    var slot = UTF8ToString(slotPtr);
    var ad = wx.createRewardedVideoAd({ adUnitId: slot });
    ad.onClose(function (res) {
      var ok = res && res.isEnded;         // isEnded 才是「看完」
      dynCall('vii', cbPtr, [ok ? 1 : 0]);
    });
    ad.show().catch(function () {
      ad.load().then(function () { ad.show(); }).catch(function () {
        dynCall('vii', cbPtr, [0]);
      });
    });
  }
});
⚠
坑微信的 res.isEnded 才是有效观看的判据。很多实现只判断 onClose 被调用就发奖，导致用户点右上角关闭也能领奖——这是最常见的漏损点。

8 构建管线：一键切版

手工切 define symbols 一定会出错。写成 Editor 脚本，让「切国际版 / 切国内版 / 切小游戏」变成菜单里的一次点击，也是 CI 的唯一入口。

C#
public enum BuildTarget2 { Overseas, Domestic, WeChat, Douyin }

public static class BuildSwitcher
{
    static readonly Dictionary<BuildTarget2, string[]> Defines = new()
    {
        [BuildTarget2.Overseas] = new[] { "USE_MAX", "USE_ADMOB" },
        [BuildTarget2.Domestic] = new[] { "USE_PANGLE", "USE_GDT" },
        [BuildTarget2.WeChat]   = new[] { "WECHAT_MINI" },
        [BuildTarget2.Douyin]   = new[] { "DOUYIN_MINI" },
    };

    [MenuItem("Build/切到国际版")]
    static void ToOverseas() => Apply(BuildTarget2.Overseas, "com.company.game", "ads_overseas");

    static void Apply(BuildTarget2 t, string bundleId, string cfgName)
    {
        var g = BuildTargetGroup.Android;
        // 清掉所有广告相关宏，再设当前这套——避免残留
        var all = Defines.Values.SelectMany(x => x).ToArray();
        var cur = PlayerSettings.GetScriptingDefineSymbolsForGroup(g)
                    .Split(';').Where(s => s.Length > 0 && !all.Contains(s)).ToList();
        cur.AddRange(Defines[t].SelectMany(x => x.Split(',')));
        PlayerSettings.SetScriptingDefineSymbolsForGroup(g, string.Join(";", cur));

        PlayerSettings.SetApplicationIdentifier(g, bundleId);
        // 再拷贝对应的 ads 配置到 Resources
        AssetDatabase.CopyAsset($"Assets/AdsConfig/{cfgName}.json", "Assets/Resources/ads.json");
    }
}
→
建议CI 里可以直接走 -executeMethod BuildSwitcher.ToOverseas，配合 -quit -batchmode，一条命令出对应版本的包。

9 Android 多渠道

国内安卓要上多个应用商店，每个渠道的广告 ID、推送 SDK、统计都有差异。用 Gradle 的 productFlavors 而不是打多个包。

Gradle
android {
  flavorDimensions "channel"
  productFlavors {
    tencent { dimension "channel"; applicationIdSuffix "" }
    huawei  { dimension "channel"; applicationIdSuffix "" }
    xiaomi  { dimension "channel"; applicationIdSuffix "" }
  }
  sourceSets {
    tencent { res.srcDirs += 'src/tencent/res' }
    huawei  { res.srcDirs += 'src/huawei/res' }
  }
}
⚠
坑渠道号不要从应用商店后台手填——容易填错且不可查。用 applicationIdSuffix 或构建时注入 manifestPlaceholders，让渠道号从构建配置派生。

10 上线检查清单

项国际版国内版
隐私政策弹窗首次启动，拒绝则不初始化 SDK同上，且必须先于任何 SDK
ATT（iOS）初始化 SDK 前弹—
GDPR / CCPA按地区下发同意流—
广告位配置走 overseas 表走 cn 表
激励视频校验MAX 的 SSV穿山甲 SSV（必做）
包名 / 签名海外包名，正式签名每渠道独立包名
测试用测试设备 ID，别点自己的真实广告同左（防作弊封号）
合规材料隐私政策 URL、数据安全表版号、软著、隐私政策、实名与防沉迷
⚠
坑最后一条最容易翻车：开发期反复点自己的广告会被平台判定为无效流量，轻则扣量，重则封号。所有测试必须用平台的测试设备白名单。
