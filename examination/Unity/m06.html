var order = new[] { "Awake", "OnEnable", "Start", "FixedUpdate", "Update", "LateUpdate", "OnDisable", "OnDestroy" };
for (int i = 0; i < order.Length; i++) Console.WriteLine($"  {i + 1}. {order[i]}");

Console.WriteLine("固定步长 0.02s（50Hz 物理）与可变帧率的对齐情况：");
double fixedStep = 0.02, acc = 0;
var rnd = new Random(7);
for (int frame = 1; frame <= 6; frame++)
{
    double dt = 0.016 + rnd.NextDouble() * 0.020;   // 16~36ms 波动
    acc += dt;
    int phys = 0;
    while (acc >= fixedStep) { acc -= fixedStep; phys++; }
    Console.WriteLine($"  帧 {frame}: deltaTime={dt * 1000,5:F1}ms  固定更新 {phys} 次  余量 {acc * 1000,5:F1}ms");
}
Console.WriteLine();
Console.WriteLine("结论：FixedUpdate 次数与帧率无关，所以物理必须放这里；Update 次数随帧率变。");

💡 ☆☆① --继承 MonoBehaviour 类

一个脚本下只能有一个类继承 MonBehaviour 类，不然会出错

Unity 定下的规则

1. 不能 new(就不需要写构造函数)，我们不会通过构造函数实例化对象

2.继承 Monobehaviour 类只能挂在在 GmaeObject 上配合使用

3.一个对象可以挂多个脚本 ，但是如果脚本中加入了 [DisallowMultipleComponent] 特性，就不能挂多个脚本

= Hierarchy文字还原

将脚本挂载到 GameObject 上，本质是为 GameObject 添加对应类型的组件实例。Unity 底层会通过反射机制，根据脚本的类型创建该脚本类的实例，将其作为组件与 GameObject 建立关联，同时完成组件的序列化、生命周期函数绑定等工作。

创建该脚本类的实例： 本质就是new 出一个该脚本类的对象实例。只是 Unity 的 MonoBehaviour 脚本有特殊规则，不能你自己手动 new，必须由 Unity 引擎帮你完成创建。

不继承 MonoBehaviour 类

1. 不继承 Mono 的类 不能挂载在 GameObject 上

2. 不继承 Mono 的类 想怎么写怎么写 如果要使用需要自己 new

3. 不继承 Mono 的类 一般是单例模式的类（用于管理模块） 或者数据结构类（用于存储数据）

4. 不继承 Mono 的类 不用保留默认出现的几个函数

02.生命周期函数的概念

游戏死循环 unity 底层已经实现，不用我们自己写。

所有继承MonoBehavior的脚本 最终都会挂载到GameObject游戏对象上

生命周期函数 就是该脚本对象依附的GameObject对象从出生到消亡整个生命周期中

会通过反射自动调用的一些特殊函数

03.生命周期函数
生命周期函数执行时机特点游戏核心用途
Awake对象诞生仅执行 1 次；物体初始隐藏也会运行缓存自身组件、初始化脚本内部变量，只处理自身
OnEnable每次激活调用物体每次激活显示时重复执行注册事件、刷新面板实时数据、开启倒计时 / 动画、怪物重置状态查
Start所有 Awake 结束后、首帧更新前，仅执行 1 次找外部 UI / 角色、绑定按钮、读取全局数据、界面初始化
FixedUpdate物理系统固定时间间隔执行，不受帧率影响刚体移动、跳跃、碰撞、击飞等全部物理逻辑
Update游戏逻辑帧更新每帧循环执行，帧率越高执行越频繁检测按键触摸、技能 CD 计时、实时刷新血条金币、普通物体移动
LateUpdate本帧全部 Update 执行完毕后统一运行相机跟随、头顶 UI / 伤害飘字坐标修正、镜头后置调整
OnDisable每次失活调用物体每次隐藏失活时重复执行，与 OnEnable 成对注销监听事件、停止协程、重置界面，避免内存泄漏
OnDestroy对象销毁时候调用对象彻底销毁 / 切换场景时仅执行 1 次，单纯隐藏不触发释放图集、贴图、音效资源，清理全局缓存

0.4生命周期函数 支持继承多态

我们要知道，虽然建议大家不在继承MonoBehavior的类中写构造函数

但是不意味着我们不能写，当我们在继承MonoBehavior的类中写无参构造函数时，你会发现在编辑模式下或者运行后，只要该脚本挂载在场景中，那么该无参构造函数是会被自动执行的。

因为Unity的工作原理中提到的反射机制，Unity实际上通过反射帮助我们实例化了该脚本对象，既然要实例化那么肯定是需要new的，只不过Unity中不需要我们自己new继承了MonoBehavior的类，只要挂载后Unity帮助我们做了这件事。

那么为什么不建议大家写构造函数呢？

1.Unity的规则就是，继承MonoBehavior的脚本不能new只能挂载

2.生命周期函数的Awake是类似构造函数的存在，当对象出生就会自动调用

3.写构造函数反而在结构上会破坏Unity设计上的规范

总结：

如果继承MonoBehavior的脚本想要进行初始化相关，可以在Awake或者Start中进行，搞清这两个生命周期函数的执行时机，根据需求选择在哪里进行初始化。

切记！！继承MonoBehavior的脚本不要new，不要new，不要new！！

答案：Unity中所有对象上挂载的生命周期函数都是在一个主线程中按先后执行的

理解：Unity会主动把场景上的对象，对象上挂载的脚本都统统记录下来，在主线程的死循环中，按顺序按时机的通过反射，执行记录的对象身上挂载的脚本的对应生命周期函数
