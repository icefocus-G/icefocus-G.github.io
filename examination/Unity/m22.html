10 万个格子为什么不能直接实例化

一个 UGUI 格子至少包含 Image + Text + Button 三个组件，加上 RectTransform 与 CanvasRenderer。1 万个就会让打开背包卡死，10 万个直接内存爆掉。真正的做法是「只渲染看得到的」——虚拟列表（Virtual List）。

方案实例化数量打开背包耗时滚动流畅度
全部 instantiate100000数十秒 / 直接卡死—
分页（每页 50）50快翻页有跳变
虚拟列表≈ 屏幕可见 + 1 行毫秒级平滑

三个必须同时做到的点

  • 占位撑高：ScrollRect.content 的高度 = 行数 × 行高，用一个空 RectTransform 撑开，让滚动条范围正确。
  • 对象池复用：只创建「可见行数 + 1」个格子，滚动时把它们挪到新位置、换数据，绝不销毁重建。
  • 只刷新差异：滚动时按索引取数据，避免整表刷新；图标用异步加载 + 占位图，防止滚动时反复 IO。

核心计算

int FirstVisibleIndex(float scrollTop, float rowHeight, int cols, int total)
{
    int row = Mathf.FloorToInt(scrollTop / rowHeight);
    return Mathf.Clamp(row * cols, 0, Mathf.Max(0, total - 1));
}

// 每次滚动只做一次：把池里的格子重新定位 + 换数据
void OnValueChanged(Vector2 pos)
{
    int first = FirstVisibleIndex(pos.y, rowH, cols, total);
    if (first == lastFirst) return;          // 行没变就不刷新
    lastFirst = first;
    for (int i = 0; i < pool.Count; i++)
    {
        int idx = first + i;
        pool[i].SetData(idx < total ? data[idx] : null);
    }
}

卡顿的四个真凶

  • Layout Rebuild：格子内用了 LayoutGroup / ContentSizeFitter，每次换数据都触发重排，一次几毫秒。能手动算位置就别用自动布局。
  • SetActive：频繁开关比改 sizeDelta 贵得多，隐藏用 CanvasGroup.alpha 或移出视口。
  • 图集切换：每滚动一屏就换一次图集，Draw Call 立刻飙升，按需分图集。
  • 同步 IO：滚动时同步读图/反序列化配置，直接掉帧，改异步 + 缓存。
