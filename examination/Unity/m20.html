HybridCLR 的原理一句话

IL2CPP 会把 C# 编译成 C++ 再编译成机器码，运行时没有 IL，所以传统上「不能热更逻辑」。HybridCLR 做的是把 IL 解释器塞进 IL2CPP 的运行时：主包仍然是 AOT 编译的，新增/改动的业务代码以 DLL 形式下发，由解释器执行。两种代码在同一进程里互相调用。

接入与热更流程

// 1) 安装：UPM 添加 HybridCLR 包 + 执行 Installer（会改 IL2CPP 源码并重新生成）
// 2) 程序集拆分：HotUpdate 程序集不参与主包编译，作为 DLL 下发
// 3) 主包里保留一个 AOT 的启动流程，负责加载热更 DLL

// 4) 运行时加载（示意）
var dllBytes = await LoadBytesAsync("HotUpdate.dll");
var pdbBytes = await LoadBytesAsync("HotUpdate.pdb");   // 可选，保留堆栈行号

Assembly hot = Assembly.Load(dllBytes, pdbBytes);
hot.GetType("Game.Bootstrap")?.GetMethod("Start")?.Invoke(null, null);

AOT 泛型：唯一会让人通宵的问题

IL2CPP 在编译期就把泛型实例「特化」成具体代码。热更 DLL 里如果用了主包从未出现过的泛型组合（比如 Dictionary<int, MyNewClass>），AOT 侧没有这份代码，运行时就会抛 MissingMetadataException。

  • 做法一：在 AOT 工程里写一个「引用补齐」静态类，把可能用到的泛型实例都 new 一遍。
  • 做法二：用 HybridCLR 的 AOTGenericReferences 扫描热更程序集，自动生成补齐代码。
  • 做法三：反射调用的方法/属性要写进 link.xml，防止被 IL2CPP 裁剪。

其它高频问题

  • 编辑器正常、真机崩：九成是 AOT 泛型缺口或裁剪，先在真机跑一轮全流程。
  • 热更代码引用了主包不存在的类：DLL 一加载就 TypeLoadException，加载顺序要保证主包类型已就绪。
  • 版本错配：主包与热更 DLL 必须成对发布，用版本号强校验，不匹配就回退。
  • 调试：保留 pdb 才能看到热更代码的行号堆栈，否则只有一串 0x 地址。
