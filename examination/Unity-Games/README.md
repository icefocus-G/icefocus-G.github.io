# Unity 小游戏源码图谱

14 个 Unity 小游戏工程的架构剖析，配一套「可玩复刻 + 逐句精讲」的课程页。

本目录有两个入口，内容是**互补的两层**，不是两套重复：

| 入口 | 是什么 | 适合 |
|---|---|---|
| `index.html`（主） | **源码图谱**：14 个工程 × 9 个页签，讲架构、类图、算法、重构与手游化 | 想搞懂「一个游戏工程是怎么搭起来的」 |
| `course.html` | **可玩课程**：13 课，每课四节（玩 → 逐句读源码 → 看运行 → 测验） | 想动手、逐行对照着写 |

图谱侧栏顶部的「🎮 可玩复刻 · 13 课逐句精讲」就是通往课程页的入口。

## 怎么打开

双击 `index.html` 即可，纯静态、无外链资源（样式与脚本全部内联在同一个文件里）。

> 单文件约 1.8MB、11,000 行，浏览器直接打开没问题；不需要服务器，也不需要安装 Unity。

## 为什么它能在 GitHub Pages 上跑

图谱原本是**本地版**：配合 `server.py` 提供三个接口，把进度和笔记写进
`data/progress.json`，这样换浏览器也不丢。

```python
/api/load   -> 读 data/progress.json
/api/save   -> 原子写入
/api/reset  -> 清空
```

静态托管没有这些接口，但图谱本身的降级逻辑是完整的：

```js
try {
  const r = await fetch('/api/load', { cache: 'no-store' });
  if (r.ok) { state.online = true; /* 合并服务器存档 */ }
  else throw 0;
} catch (e) {
  state.online = false;   // 离线：只写 localStorage
}
```

`state.online` 为 false 时，`save()` 只调 `saveLocal()`，不再发请求。所以
**放到 Pages 上自动降级为「本机保存（localStorage）」，无需任何后端**。
侧栏底部那行状态就是它的自述：连不上服务器时显示「本机保存」。

> 代价：进度/笔记只存在当前浏览器。要跨设备同步得另接一个存储（或保留
> `server.py` 在本机跑）。

## 这份图谱是怎么进来的

从交付物 `01-小游戏源码图谱` **原样迁入**（单文件，正文与数据一字未动），
只做了三处改动：

1. 侧栏「搜索框」下方注入一个通往 `course.html` 的入口卡片（`.xplay`）；
2. 配套几行 `.xplay` 样式；
3. 把降级提示的「离线模式（localStorage）」改为「本机保存（localStorage）」——
   静态托管下本来就该是常态，说「离线」会让人以为坏了。

原来的课程页（13 课）没有删，只是从 `index.html` 改名为 `course.html`，
链接与资源路径全部不变。
