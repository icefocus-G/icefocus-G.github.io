# 识字卡片

给小朋友做识字表 / 词组表的单页应用。字库和词库都在 `data/dict.json` 里，改完就能用，不需要改代码。

**已上线：<https://icefocus.cn/shizi/>**（部署在 GitHub Pages 仓库 `icefocus-G/icefocus-G.github.io` 的 `shizi/` 目录）

- 学拼音：声母 / 韵母 / 整体认读音节 / 四声 / 拼读规则，卡片上只有字母和它的读音，点一下读出来并打勾
- 识字表：A4，每行 8 个、共 11 行，多的顺延到下一张
- 词组表：**跟着识字表自动匹配**——凡是用到的字都在识字表里的词就会出现，按 2 字 / 3 字 / 4 字分组，可一键定位。
  人工精选的词排前面，剩下的从 6 万条候选词池里按使用频率自动补，每个字最多贡献 6 条，生僻字也有词、高频字不霸屏
- 汉字上方都带拼音（词组表是逐字对齐的注音），顶栏 `拼音开 / 拼音关` 一键切
- **点字就能听**：学拼音卡、识字表、词组表、年级挑字都能点着读，5747 条语音预生成，断网也能读
- 按年级挑字：顶栏下拉选一年级～六年级，出课本识字表（带拼音），点着挑、批量加入识字表
- 手机上手指左右滑、电脑上按住鼠标左右拖，就能翻上一张 / 下一张
- 每个页面都能导出 300dpi PNG 或直接打印
- 隐藏文字、随机排序、田字格辅助线
- 卡片字体可切 楷体 / 宋体 / 黑体（宽屏在顶栏，窄屏在「更多」里），导出的 PNG 也跟着变。
  卡片、词组表、加字面板、打印页读的是同一个变量 `--font-card`（挂在 `<body>` 上），
  **新加的汉字样式别再写死 `var(--font-kai)`**，否则那块换字体时不动
- 页面高度用 `100dvh` 而不是 `100vh`：iPad / iPhone 的 `100vh` 把地址栏、工具栏的高度也算进去了，
  底部分页栏会被推出屏幕只露一半。滚到底允许橡皮筋回弹（不用 `overscroll-behavior:contain`）

## 点字就能听（语音）

**点哪里会读什么**

| 位置 | 点一下 |
|---|---|
| 学拼音的卡片 | 读字母本音（`b` → bō，不是例字「爸」） |
| 识字表的格子 | 读这个字 |
| 词组表的格子 | 读整个词（「蝌蚪」读 kē dǒu，不是一个字一个字蹦） |
| 按年级挑字的卡片 | 读这个字，同时选中 / 取消 |

- 读的时候那一格会**闪一下红底**，孩子知道在读哪个
- 顶栏 `声音开`（红色＝开着）/ `声音关` 一键静音，状态存在本地；手机上按钮缩成 `声音` / `静音`，两种状态字数一样，不会跳动
- 连点两个格子时，后一句会打断前一句，不会叠在一起
- 「隐藏文字」模式下点一下＝把这个字露出来 + 读出来，正好当认字测验用

**声音从哪来**

`data/audio/` 里是预先生成好的 mp3（微软 edge-tts，音色 `zh-CN-XiaoxiaoNeural`，语速 -10%），共 6741 条：

| 内容 | 条数 |
|---|---|
| 单字（拼音表 4030 字，含年级课本与词库用字） | 4035 |
| 词（`dict.json` 的人工词库 + 词池里「字全在默认识字表内」的词） | 2706 |

清单文件 `data/audio/manifest.json` 就是「文字 → 语音文件」的绑定表：

```json
{ "version": 1, "voice": "zh-CN-XiaoxiaoNeural", "rate": "-10%",
  "chars": { "天": "3f/5929.mp3", "蝌": "36/874c.mp3" },
  "words": { "蝌蚪": "3e/874c-86aa.mp3" } }
```

- 文件按**文字码点**命名（`天` → `5929.mp3`，`蝌蚪` → `874c-8679.mp3`），纯 ASCII，不会因为中文文件名在服务器上出乱码
- 按文字哈希分到 64 个子目录，避免一个目录堆六千个文件
- `manifest.js` 是同一份清单的脚本版，`file://` 双击打开时用它兜底（和 `dict.js` / `grades.js` 一个套路）

**没有对应 mp3 的字怎么办**

退回浏览器自带的语音合成（Web Speech API，系统里装了中文语音就能读）。所以用户自己加的生僻字、自己写的自定义词组也会有声音，只是音色跟着系统走。

**改词库以后要重新生成语音**

```bash
python tools/build-audio.py          # 增量：已有的跳过，只补新词
python tools/build-audio.py --force  # 全部重来
python tools/build-audio.py --limit 20   # 只做前 20 条，调试用
```

需要 `pip install edge-tts`。脚本会顺带重写 `manifest.json` / `manifest.js`，前端不用改。

**点下去就出声：先取到本地再播**

页面渲染完会把**当前这张纸上的音**（88 条，约 700KB）在后台悄悄下好，存成 blob：

- 点击时直接播放本地那份，**不等网络**，也不需要再发请求
- 最多留 300 条（`BLOB_MAX`），超出就回收最早的，翻多少页都不会把内存吃满
- 没来得及预取的字（比如刚翻页就点）走普通地址，也能播，只是要等那 8KB 下载完
- 翻页、切换视图都会重新预取；学拼音页 67 张卡一次备齐

**iPad / iPhone 上没声音？**

以前 iPad 上点了不出声、电脑上正常，有两个原因，现在都处理了：

1. **Service Worker 把 mp3 也接管了**
   Safari 播放 `<audio>` 时会先发 `Range` 请求，Service Worker 返回的是缓存里那份完整的 `200`，不是 `206`，Safari 就判定「服务器不支持分段」然后静默不出声。桌面 Chrome 宽容，所以看不出来。
   现在 `sw.js` 对 `/data/audio/` 下的 mp3 **直接放行**（`if (isVoiceFile || req.headers.has("range")) return;`），交给浏览器自己和 CDN 协商（CDN 本来就有 `206` + `max-age=14400`）。

2. **iOS 对自动播放管得严**
   改成**全程复用同一个 `<audio>` 元素**（挂在 DOM 里），不再每次 `new Audio()`；播放都在点击的同步调用栈里，`src` 赋值后直接 `play()`、不多调 `load()`（多调会把刚起来的播放打断成 `AbortError`）；系统语音兜底也改成同步调用，不再放在 `.catch()` 里（iOS 上异步调 `speechSynthesis` 是无声的）。

**还是没声音，按这个顺序查**（地址后面加 `?diag=1` 会弹出左下角的自检面板）：

1. **iPad 侧边那颗静音键**——它一开，网页音频一样静音，这是最常见的
2. 音量键调一下，别是耳机插着
3. Safari 设置 → 网站设置 → 自动播放：选「允许」
4. 点面板里的「试听一下『天』」，再看「最近一次播放错误」那一行：
   - `NotAllowedError` → 浏览器没把手势算进来，刷新页面再点
   - `NotSupportedError` / `NotReadableError` → 文件没解出来，检查网络
   - 空白 → 文件播成功了，就是设备静音，回到第 1 条

**离线**

`sw.js` 不缓存 mp3（原因见上），离线时点读会退回系统语音。**不再预缓存音频**，避免再踩 Safari 的 Range 坑。

## 拼音怎么显示 / 隐藏

识字表和词组表的每个字上面都有拼音，词组表是**逐字对齐**的（`kē dǒu` 分别压在「蝌」「蚪」上），打印和导出的 PNG 里也都带拼音。

- 顶栏 `拼音开`（红色＝开着）点一下变 `拼音关`，只把拼音那一行藏起来，**汉字大小、位置、格子间距完全不变**（不会因为关拼音让字变大、行距变宽）
- 开关状态存在浏览器本地，下次打开保持上次的选择
- 电脑和手机用同一套写法（`拼音开` / `拼音关`），字数不变，点的时候按钮宽度和文字位置都不动
- 拼音数据来自 `data/pinyin.json`：4030 个常用字的读音 + 197 条多音字词组修正（例如「长大」标 `zhǎng dà` 而不是 `cháng dà`）。课本字表的读音优先用 `grades.json` 里教材的注音
- 字库里如果有表里没收录的生僻字，那个字只是不显示拼音，排版不受影响

改拼音数据：

```bash
python tools/build-pinyin.py     # 重新生成 data/pinyin.json
node   tools/build-data.js       # 顺便生成 data/pinyin.js（双击打开时兜底）
```

想给某个字点修读音，改 `tools/build-pinyin.py` 里的 `FIX` 字典再重跑；想批量换源就改 `TOP_SINGLE`（默认收 jieba 词频里最常用的 3600 个单字）。

## 学拼音怎么用

最左边的 `学拼音` 导航，是给家长带着孩子过一遍拼音用的速查页：

- 声母 23 个、单韵母 6 个、复韵母 9 个、前鼻韵母 5 个、后鼻韵母 4 个、整体认读音节 16 个
- 每张卡片是「字母 + 它自己的读音」，例如 `b / bō`、`an / ān`、`zhi / zhī`。
  **不显示例字**：以前 `b` 下面写「爸」、点读也读「爸」，孩子会以为 b 就念 bà；
  现在读的是声母的呼读音（`b` 读 bō，和课本一致），字母和读音一一对应
- 四声做成一张小表：`a o e i u ü` 六个韵母 × 四个调，24 格，格子里只写带调的韵母本身
  （`ā á ǎ à`）。点哪格读哪格，**不带声母**——点 `á` 就是 á，不是「麻」。
  音频是 `tools/build-tones.py` 用真实录音剪掉声母做出来的，见下面「四声表的音」
- 底下两块文字：拼读规则（两拼三拼、`j q x` 遇 `ü` 去两点、标调顺序、轻声）和容易混的地方（`b d p q`、平翘舌、前后鼻音、`n/l`、`f/h`）
- 点卡片会读卡片自己的音，同时打勾，方便在屏幕上一个个过，讲完再取消

内容全部写死在 `index.html` 的 `PY_LESSON` / `PY_TONE_SETS` / `PY_RULES` / `PY_TRAPS` 里。

`PY_LESSON` 每项是三个字段：

```js
["b", "bō", "玻"]
//  ^符号  ^标注（卡片上显示）  ^读哪个字（只给语音用，不显示）
```

第三项必须是一个**汉字**——`tools/build-audio.py` 会从 `index.html` 里把这一列抓出来，
确保每个符号都有对应的 mp3。声母用课本的呼读音字：玻 坡 摸 佛 得 特 讷 勒 哥 科 喝 基 欺 希
知 吃 诗 日 资 次 思 衣 乌；韵母用 啊 喔 婀 迂 哀 诶 威 凹 欧 优 耶 约 儿 安 恩 因 温 晕 昂 鞥 英 翁。

改了这张表之后跑一次 `python tools/build-audio.py`，缺的音频会自动补上（只补新的）。

**四声表的音（`data/audio/tone/`）**

两条路都试过，都不行：

1. 直接让 TTS 读带调拼音 —— 实测 edge-tts 读 `ó` 是平调、读 `ě` 是降调；
   SSML 的 `<phoneme>` / `<prosody contour>` 会被 Edge 端点拒收（NoAudioReceived）。
2. 拿「拔 bá / 把 bǎ / 爸 bà」的录音剪掉声母 —— 爆破音剪完还留着一下「b」，
   听起来还是 ba / bo / da。

所以现在是第三种：**拿单元音本身的录音，用 PSOLA 把音高改成四个调**。

```bash
python tools/build-tones.py     # 24 条，依赖 soundfile + lameenc
```

素材只用六个纯元音的第一声（啊 喔 婀 衣 乌 迂 —— 本来就是零声母，干净的元音），
取中间那段稳定元音做「音源」，然后按 `TONES` 里的曲线做基音同步叠加（PSOLA）：

- 一声 55：平的
- 二声 35：从 -1.5 半音升到 +5
- 三声 214：先降到 -3.6 再回升到 +1.2
- 四声 51：从 +2.6 一路降到 -7

PSOLA 只改基音、不改共振峰，所以元音还是那个元音，变的只有声调 —— 这正是要教的东西。
格子里的 `ā á ǎ à` 和声音的调一一对应。脚本跑完会打印每条的实测音高曲线自检。

它写进 `manifest.json` 的 `tones` 字段（`{"ā": "tone/a1.mp3", …}`），前端 `speak()` 会查这张表。

## 翻页：滑动 / 拖动

纸不是「一张在原地晃」，而是一条**三张并排的纸带**在一个跟纸一样大的窗口里滑动：
窗口固定不动、负责裁边和投影，纸带里放着「上一张 / 当前张 / 下一张」，滑的时候
当前这张从窗口一边被抽走、下一张同时从另一边补上来，中间那条缝有阴影，看着就是
实实在在翻过去了一张纸。

- **手机**：在纸面区域手指左右划，纸带 1:1 跟手；划过整页宽度的 18% 松手就翻，
  没到就弹回原位；**甩一下**（够快）也翻，慢拖到头不翻
- **电脑**：在纸面上按住鼠标左键左右拖，规则同上
- 松手时剩下的路按剩余距离算时间（0.22～0.46s），不会因为已经拖了一半而拖拖拉拉
- 到头（第一张往右、最后一张往左）没有隔壁纸，只给橡皮筋阻尼、松手回弹
- 上一张 / 下一张按钮、键盘 ←→ 也走同一套整页滑动动画
- 拖动过之后不会误触发格子点选；只在识字表和词组表生效，「加字」「按年级挑字」
  「学拼音」是滚动列表，不受影响

实现要点见 `index.html` 里的 `.paper-window`（窗口，`overflow:hidden` + 投影）与
`.paper-wrap`（纸带，`position:absolute;inset:0`，只有它被 `translateX`）；
`renderNeighbors()` 负责把左右两张画好，`slideTo()` 负责滑完剩下的一页并在落地的
同一帧换页复位（先 `transition:none` 复位，再 `goPage()`，然后读一次 `offsetWidth`
强制布局，避免中间闪一帧旧内容）。

## 按年级挑字怎么用

顶栏 `识字表 / 词组表 / 加字` 右边的下拉框，选「一年级」～「六年级」，会切到该年级的识字表：

- 每张卡片是「拼音在上、汉字在下」，灰色是字库里已经有的，点一下就选中（打勾变红）
- `全选 / 清空选择 / 反选` 在左边，右边显示「已选 N 字」
- 点 `加入识字表` 就批量入库，自动回到识字表并提示新字库字数、词组条数变化
- 加错了去「加字」页点撤销（撤销记录是同一份）

年级字表在 `data/grades.json`，结构很简单，想增删直接改这个文件：

```json
{ "grades": [ { "grade": 1, "name": "一年级", "chars": [["天","tiān"], ["地","dì"]] } ] }
```

改完跑 `node tools/build-data.js` 重新生成 `data/grades.js`（双击打开时用它兜底）。

## 三种用法

### 1. 本地直接打开（最简单）

双击 `index.html` 或 `启动.bat`。

浏览器在 `file://` 下禁止用 `fetch` 读本地文件，所以页面会自动改用 `data/dict.js`。
**因此：改完 `dict.json` 必须重新生成一次 `dict.js`**

```bash
node tools/build-data.js
```

### 2. 本地起一个服务（改 json 立刻生效）

```bash
cd kid-cards
python -m http.server 8080      # 或者 npx serve
```

浏览器打开 <http://localhost:8080>。这种方式下页面直接读 `dict.json`，不用重新打包。

### 3. 部署到 GitHub Pages

1. 新建仓库，把 `kid-cards` 里的**全部文件**传上去（`index.html` 要在仓库根目录）
2. 仓库 Settings → Pages → Source 选 `Deploy from a branch`，分支 `main`，目录 `/ (root)`
3. 等一两分钟，访问 `https://<用户名>.github.io/<仓库名>/`

注意：

- 目录名和文件名**区分大小写**，`data/dict.json` 必须原样保留
- 用 GitHub 网页上传时，`data` 文件夹要一起拖进去
- 部署后手机上用 Safari / Chrome 打开，菜单里「添加到主屏幕」就是全屏 App 的样子，且支持离线

## 词库怎么改

`data/dict.json` 结构如下：

```json
{
  "version": 3,
  "updated": "2026-11-05",
  "note": "说明文字，随便写",
  "defaultChars": "猫扣妈瓜爸粉……",
  "words": {
    "2": ["妈妈", "爸爸", "……"],
    "3": ["幼儿园", "……"],
    "4": ["万水千山", "……"]
  }
}
```

- `defaultChars`：第一次打开时的默认字库（之后用户在页面里加的字存在浏览器本地，不会写回这个文件）
- `words`：按字数分好组的词库。**数组的先后顺序就是「默认排序」的顺序**，想让孩子先看到哪批词，就把它放前面
- 删掉某个词：直接从数组里删。加词：加进对应长度的数组即可
- 页面里只显示「所有字都在字库里」的词，所以加词不会立刻显示，要等字库里也有这些字

改完执行 `node tools/build-data.js`。

## 词组表怎么「自动匹配」

词组表 = **人工词库（`dict.json`）+ 词池自动补（`wordpool.json`）**，两段都按当前识字表实时筛：

1. 先放自己加的 `customWords` 和 `dict.json` 里的人工词（顺序就是人工排的顺序，最贴孩子的排在前面）
2. 再从 `wordpool.json` 的 6 万条候选词里，挑「每一个字都在识字表里」的词，按词频从高到低补上

所以**识字表变了，词组表立刻跟着变**，不需要改任何数据文件：

```
识字表里加了「田」 → 词组表立刻出现 田地 / 稻田 / 瓜田 / 田园
识字表里删掉「梨」 → 梨花 / 梨子 / 梨园 一起消失
```

**每个字最多 6 条（`index.html` 里的 `WORD_QUOTA`）**。不设这个配额的话，「大」「人」「心」这种高频字会占掉几十条，
生僻字组的词被挤到几十页以后；设了配额，每个字都有词，孩子顺着认完 163 个字就能读到 800 多个词。

`wordpool.json` 由 `tools/build-words.py` 从分词词典（`tools/jieba_dict.txt`）生成，规则：

| 规则 | 原因 |
|---|---|
| 只收 2 / 3 / 4 字、全是汉字 | 词组表就这三种格子 |
| 词频 ≥ 10 | 更低频的两字组合大量是「水禾、金音」这种生造搭配 |
| 去掉人名 / 地名 / 机构名 / 量词 / 代词 / 虚词（`nr ns nt nz m r q p u …`） | 「宝鸡」「李自成」不该出现在识字卡里 |
| 每个字都得在 4030 常用字表（`pinyin.json`）里 | 挡住「龃龉」这类连家长都不认识的词 |

改了规则就重跑：`python tools/build-words.py`（600KB，前端只在打开词组表时才下载）。

**词池里的词也要有声音**：`tools/build-audio.py` 会把「字全在默认识字表内」的词池词一起做进 `data/audio/`，
识字表以后加了很多新字，记得再跑一次，否则新词点读会退回系统语音。

## 打包成安卓 / iOS App（可选）

```bash
mkdir shizi-app && cd shizi-app
npm init -y
npm i @capacitor/core @capacitor/cli

npx cap init "识字卡片" com.example.shizi --web-dir=www

npx cap sync

```

Capacitor 内部是用 `http://localhost` 提供页面的，所以 `fetch('data/dict.json')` 正常工作，`sw.js` 也会生效。

如果只是想在手机上给孩子用，**其实不必打包**：用浏览器打开后「添加到主屏幕」效果基本一样，还省掉签名和上架。

## 数据存在哪

- 字库、自定义词组、字体、排序方式存在浏览器的 `localStorage` 里（键名 `shizi_cards_v1`）
- 换设备 / 换浏览器不会自动同步，用「字库 → 导出 JSON / 导入 JSON」搬运
- 换电脑时如果只想带走词库本身，改 `data/dict.json` 更彻底

## 已知限制

- `file://` 下不注册 Service Worker，因此没有离线缓存（本来也不需要，文件都在本地）
- 本地双击打开时，改 `dict.json` / `pinyin.json` 不生效，必须重新跑 `build-data.js`
- 打印请用 A4、边距选「无」或「默认」、勾选「背景图形」，否则田字格虚线印不出来
- 拼音表只收常用字（约 4030），生僻字和不认识的字不显示拼音（不报错、不占错位）
- 语音必须由用户先点一下（浏览器不允许页面自动出声）；iPad / iPhone 打开侧边静音键时网页音频也会被静音
- `sw.js` 不缓存 mp3（Safari 的 Range 限制），所以断网时点读会退回系统语音；页面内的 blob 预取只对当前这张纸有效
- 预取会给每张纸多下约 700KB（88 个音），流量紧张时可以只打开「声音」再翻页

## 词库来源与筛选规则

词库**全部是人工编排**的，共 1,718 条（2 字 1,322、3 字 173、4 字 223），分两部分：

1. **精选核心**（1,289 条）：按「家人、身体、食物、动物、植物、自然、时间、动作、情绪、学习、家居、交通、衣物、颜色、方位、职业」等生活认知分类手工编排，数组里排在最前面
2. **手写补充**（429 条）：`tools/kid-words.js` 里按分类维护，包括季节、天气、叠词、成语、寓言故事类

### 为什么不再用词频表自动筛

结巴词频表来自**新闻语料**，里面「高频词」是经济、常委会、阶级斗争这类词，而儿童日常词在新闻里频率很低。实测过几条路都走不通：

| 尝试 | 结果 |
|---|---|
| 词频 ≥ 300 | 混进「好色、女公、奶子」 |
| 词频 ≥ 3000 | 反而更多「经济、常委会、阶级斗争」 |
| 按词性过滤（去 nr/ns/nt） | `李自成` 标的是 `nrfg`，漏了 |
| 按常用字过滤 | 「人民政府」用的全是常用字，挡不住 |
| 限定儿童字域 | 仍漏「阴道、镇压、垄断、清军」 |

结论：新闻语料里没有「儿童词库」，怎么过滤都会有残留。所以**主词库**改成人工编排。

词频表后来的用途变了：它不再决定「孩子看到哪些词」，而是**在人工词库之外补齐识字表的覆盖**
（`wordpool.json`，见上面「词组表怎么自动匹配」）。人工词排在前面，所以即便词池里混进个别
「人大」「分子」这类不那么儿童向的词，也只会在很后面的页里出现，不影响第一屏。`build-dict.js`
仍然会用词频表校验手写词有没有错字。

### 改词库的三种方式

- 临时加几个词组 → 直接改 `data/dict.json` 的 `words`
- 想让孩子学某个字就能读到相关的词 → 不用加词，把字加进识字表即可（词池会自动匹配）
- 成批加 → 改 `tools/kid-words.js` 对应分类，跑 `node tools/build-dict.js && node tools/build-data.js`
- 想恢复旧的大词库（1.24 万条，含新闻词） → 用 `tools/dict.old-12380.json` 覆盖 `data/dict.json` 再跑 `build-data.js`
